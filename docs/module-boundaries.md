# 模块边界

## Login

负责登录页、社交登录按钮、协议弹窗和本地登录态入口。不负责用户档案编辑。

## Splash

负责开屏展示。不承载业务状态。

## Profile

负责用户个人护肤档案的采集与维护，包含性别、年龄、肤质、肤色、脸型、皮肤问题、安全避雷和偏好注意事项。档案详情由后端 `profiles` 模块和 `user_profiles` 表独立承载，不写入 `users` 账号主表。

## Settings

负责用户系统级账户安全与视觉标识，包含修改登录用户名、绑定手机号、上传真实头像及三方账号管理。其处理的数据严格落入 `users` 主表与 `user_social_auths` 表中，严禁在 Settings 中采集或展示业务相关的护肤属性。

## Product

负责产品搜索、产品详情、个人产品库、成分事实展示和产品适配分析。当前产品详情需要展示产品基础信息、备案号、品牌起源、完整成分表、功效分组、安全提示和结合个人档案的亮点/Tips。

产品模块可以读取用户档案用于适配分析，但不负责编辑个人档案；只有完全没有档案时才提示跳转 `Profile`。已有档案时，产品详情 Tips 应结合产品成分和已有档案动态生成，不写固定模板。

产品库列表进入详情再返回时，必须保留搜索词、懒加载进度和滚动位置。已加入个人产品库的产品详情应显示已加入状态，并由后端兜底避免重复添加。

档案里的“不方便透露”默认值保持不变；在产品适配规则中按未孕状态处理，只有备孕、怀孕、哺乳触发孕哺谨慎规则。

## Chat

负责 AI 问答主入口、多会话消息流、历史会话管理、结构化回答渲染和脱敏问答日志。用户登录进入 `/chat` 默认展示新空会话；第一条消息发送后才创建历史会话；历史会话只在侧边栏历史区展示，不作为普通导航入口展示。

Chat 当前已接入 DeepSeek。后端必须先执行本地意图、安全和上下文策略，再调用模型生成结构化答案；模型异常时必须回退到本地结构化答案。当前模型上下文只取最近 8 条消息，V3 需要加入长期摘要与压缩历史会话能力。

Chat 后端必须通过登录态解析用户身份，严禁通过 query/body 中的任意 `user_id` 读写会话。

## 全局规则

新增能力必须先明确所属模块，再补页面、API、service、repository 和 migration。涉及历史记录或个人隐私的数据，必须按当前登录用户隔离访问。

前端调用个人档案、个人产品库、产品适配分析、设置中心等当前用户相关接口时，不得在 URL、query 或 body 中传入任意 `user_id`；后端统一通过登录态解析当前用户。公开产品搜索可以不读取登录态。
