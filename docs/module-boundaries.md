# 模块边界

## Login

负责登录页、社交登录按钮、协议弹窗和本地登录态入口。不负责用户档案编辑。

## Splash

负责开屏展示。不承载业务状态。

## Profile

负责用户个人护肤档案的采集与维护，包含性别、年龄、肤质、肤色、脸型、皮肤问题、安全避雷和偏好注意事项。档案详情由后端 `profiles` 模块和 `user_profiles` 表独立承载，不写入 `users` 账号主表。

## Settings

负责用户系统级账户安全与视觉标识，包含修改登录用户名、绑定手机号、上传真实头像及三方账号管理。其处理的数据严格落入 `users` 主表与 `user_social_auths` 表中，严禁在 Settings 中采集或展示业务相关的护肤属性。

## Product

当前只保留产品库入口和空状态。添加产品、删除产品、反馈、产品分析都暂停，后续作为产品模块能力重新设计。

## Chat

负责 AI 问答主入口、多会话消息流和历史会话管理。用户登录进入 `/chat` 默认展示新空会话；第一条消息发送后才创建历史会话；历史会话只在侧边栏历史区展示，不作为普通导航入口展示。Chat 后端必须通过登录态解析用户身份，严禁通过 query/body 中的任意 `user_id` 读写会话。

## 全局规则

业务模块不得使用旧模拟数据。新增能力必须先明确所属模块，再补页面、API、service、repository 和 migration。涉及历史记录或个人隐私的数据，必须按当前登录用户隔离访问。
