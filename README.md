# 智颜

智颜是一个面向个人肤况的专属 AI 护肤决策系统。它把用户档案、产品成分事实、适配分析和 AI 问答串成一个闭环，帮助用户更有依据地理解“**我适合什么、该避开什么、下一步怎么护理**”。

## 设计思路

护肤用户常见的痛点是：信息很多，但难以判断是否适合自己。成分说明、产品测评和护理建议往往偏通用，无法同时考虑个人肤质、皮肤问题、过敏情况、孕哺状态和正在使用的产品组合。

智颜的设计重点是“专属”。系统先沉淀个人肤况档案，再结合产品库中的成分、功效和风险信息，把通用产品事实转化为贴近个人情况的适配判断。

AI 的作用是降低理解和决策成本。用户可以用自然语言提问，系统再把个人档案、产品事实和适配分析转化为更容易理解、可以继续追问的建议。

最终目标是让用户不只是“看产品”，而是围绕自己的肤况和产品，**形成一套专属、可追溯、可解释、可继续扩展的 AI 护肤辅助系统**。

### 当前版本 1.0
当前版本已完成最小可用的护肤决策闭环。

1. 用户可以建立并维护自己的肤况档案。
2. 系统已经沉淀产品、成分、功效和风险等基础事实。
3. 适配分析已经可以把“产品事实”和“个人情况”连接起来。
4. AI 问答已经可以承接用户的自然语言问题，并保留多会话历史。

💗 亮点：当前版本已经跑通“**个人档案 -> 产品事实 -> 适配分析 -> AI 问答 -> 历史沉淀**”的基础路径，让用户可以围绕自己的肤况和产品，形成一套可追溯、可解释、可继续扩展的护肤辅助系统。

## 核心功能模块

### 1. 个人肤况档案
个人档案用于建立推荐和分析的基础上下文，包含：

- 肤质、肤色、脸型等基础特征。
- 痘痘、泛红、闭口、敏感等皮肤问题。
- 已知过敏信息、孕哺状态、经期痘等安全避雷条件。
- 个人偏好、禁忌和护理习惯说明。

这些信息不写入账号主表，而是由独立的个人档案模块维护，方便后续扩展更细的肤况字段。

### 2. 产品库与成分事实
产品库用于沉淀产品级和成分级事实，当前包括：

- 产品搜索、产品详情和个人产品库。
- 产品品牌、分类、图片、备案号、来源链接等信息。
- 包装成分表、成分安全等级、使用目的和功效标签。
- 产品功效分组，例如保湿、修护、防晒、抗氧化、持妆、妆效修饰等。

产品库不是简单展示清单，而是后续适配分析和 AI 问答的事实基础。

### 3. 产品适配分析
适配分析负责把“产品成分”与“用户档案”连接起来，当前支持：

- 根据成分标签生成产品功效亮点。
- 根据酒精、香精、酸类、视黄醇、致痘风险等标签生成安全提示。
- 根据敏感肌、痘痘闭口、过敏信息、孕哺状态等个人条件给出谨慎或避雷建议。
- 当档案信息不足时，提示用户补充关键字段，而不是给出过度确定的判断。

这一层是项目的核心逻辑之一：它让产品详情不只是“看成分”，而是变成“结合我自己怎么看这个产品”。

### 4. AI 问答与历史沉淀
用于承接用户的自然语言问题，例如“我最近长痘怎么办”“这两个产品能不能一起用”“今天面试想画淡妆”。当前支持：

- 多会话问答。
- 历史会话回看。
- 会话重命名和软删除。
- 登录态鉴权，按当前用户隔离会话。
- 对用户问题做脱敏日志记录，为后续知识库建设做准备。

当前回答以本地结构化规则为主，已经预留 OpenAI 配置入口。后续可以把真实大模型、产品知识库和个人长期记忆接入到这一层。

### 5. 工程支撑能力
为了让核心闭环可以在真实用户场景中稳定运行，项目还实现了：

- 账号体系、登录态和用户数据隔离。
- 头像上传、设置中心和个人资料维护。
- 前后端统一接口封装和统一响应结构。
- Alembic 数据库迁移和可追踪的数据结构演进。
- 后端模块化分层：router、schemas、models、service、repository。
- 后端接口测试和前端构建验证。

这些能力共同构成完整应用的工程底座，说明项目不仅是功能演示，也在按真实用户系统的方式处理身份、数据隔离、资料维护和长期可维护性。

## 版本说明

### V1：护肤决策闭环基础版
版本目标：完成“个人档案 + 产品库 + 成分/适配分析 + AI 问答多会话”的基础闭环。

1. 用户可以维护自己的个人肤况档案。
2. 用户可以搜索产品、查看产品详情，并把产品加入个人产品库。
3. 系统可以基于产品成分和用户档案生成适配分析、安全提示和补档案建议。
4. 用户可以通过 AI 问答提出护肤、妆容和产品搭配问题。
5. AI 问答支持多会话、历史回看、重命名、软删除和脱敏日志。
6. 项目具备基础工程规范：模块边界、数据库迁移、测试用例、构建检查和上传前文件审查。

💗 亮点：已经验证一条完整路径：用户档案 -> 产品事实 -> 成分/适配分析 -> 对话式建议 -> 历史沉淀。

### V2：真实大模型接入（待完成）
目的：真正连接大模型生成答案。

1. 接入真实大模型，让 AI 回答从本地规则升级为模型生成。
2. 将个人档案、产品库和历史会话作为回答上下文。
3. 根据护肤、妆容、产品搭配等不同问题生成结构化答案。

💗 亮点：让 AI 不只回答通用问题，而是基于用户自己的资料生成更专属的建议。

### V3：AI 答案精细化（待完成）
目的：让 AI 生成的答案更可读、可追问、可解释。

1. 对答案中的关键词、成分、产品、肤况实体做特殊标记。
2. 用户点击标记后，可以继续查看解释、风险、使用建议或相关产品。
3. 把长答案拆成更清晰的结构，例如结论、原因、步骤、提醒。

💗 亮点：让 AI 答案从“一段文字”升级为可交互、可继续深入理解的护理建议。

### V4：缺失产品自动补全（待完成）
目的：解决产品库中没有目标产品时，用户无法继续分析的问题。

1. 当用户搜索不到产品时，允许发起产品补全流程。
2. 自动获取品牌、名称、分类、成分、备案号、来源链接等可核验数据。
3. 数据经确认后写入产品库，再进入适配分析和 AI 问答流程。

💗 亮点：让产品库从固定数据集，逐步变成可增长、可校验的产品知识库。

### V5：AI 拍照录入个人档案（待完成）
目的：降低用户填写个人档案的成本。

1. 用户通过拍照上传面部状态。
2. AI 辅助识别肤况线索，例如泛红、痘痘、暗沉、肤色和面部特征。
3. 将识别结果转化为可编辑的个人档案字段，由用户确认后保存。

💗 亮点：让个人档案从手动填写，升级为“AI 初步分析 + 用户确认”的录入方式。

🌟 说明：V2-V5 都是规划方向，不表示这些能力已经完成。

## 技术架构

项目采用前后端分离架构：
- 前端：Vue 3、Vite、Pinia、Vue Router、Axios、SCSS
- 后端：FastAPI、SQLAlchemy、Alembic、Pydantic
- 数据库：默认 SQLite，可通过 `DATABASE_URL` 切换
- 静态资源：产品图和用户头像由后端 `/static` 提供

后端是模块化单体结构，当前主要模块包括：
- `users`：账号和登录相关能力。
- `profiles`：个人肤况档案。
- `products`：产品库、成分库和适配分析。
- `chat`：AI 问答、多会话和脱敏日志。


## 本地启动

### 1. 准备环境
- Python 3.11+
- Node.js 18+
- npm

### 2. 启动后端
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

./.venv/bin/alembic -c backend/alembic.ini upgrade head
./.venv/bin/python -m uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
```

常用地址：
- 健康检查：`http://localhost:8000/api/health`
- API 文档：`http://localhost:8000/docs`

### 3. 启动前端
```bash
cd frontend
npm install
npm run dev
```

默认 Vite 端口为 `6688`。前端开发环境会把 `/api` 和 `/static` 代理到后端 `http://localhost:8000`。

## 环境变量

后端常用环境变量：
| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `DATABASE_URL` | 数据库连接 | `sqlite:///backend/data/miyang.db` |
| `OPENAI_API_KEY` | OpenAI API Key，可选 | 空 |
| `OPENAI_BASE_URL` | OpenAI 兼容服务地址，可选 | 空 |
| `AI_MODEL` | 预留 AI 模型名 | `-` |
| `CORS_ORIGINS` | 跨域来源 | `*` |

前端环境变量参考 `frontend/.env.example`。个人本地覆盖请使用 `.env.local` 或 `.env.*.local`，这些文件不会提交。

## 开发约定
- 新功能先判断所属模块，再补齐前端页面、API、后端 router、schema、service、repository 和必要 migration。
- 涉及数据库结构变化必须新增 Alembic migration。
- 涉及用户隐私的数据必须从登录态解析当前用户，不信任客户端传入任意 `user_id`。
- 提交前不要包含 `.env`、`.DS_Store`、`__pycache__/`、`*.pyc`、`.venv/`、`node_modules/`、`frontend/dist/`、本地数据库等文件。
- 长期规范放在 `docs/` 根目录；阶段性审计和专项治理放在 `docs/audits/`。

## 分支约定
- `basic-service`：基础业务主线。
- `ai-answer`：AI 问答相关开发分支。
- `pro-env`：同步部署或正式环境分支。
